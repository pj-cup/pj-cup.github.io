# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static GitHub Pages site publishing standings and head-to-head results for a tennis league ("PJ Cup"). There is no server and no client-side data fetching — `docs/` is a fully pre-rendered static site regenerated from CSV data by a Python build script.

## Commands

Regenerate the site after adding or editing a CSV snapshot:

```
python3 build.py
```

Check that a snapshot's head-to-head grid and standings table are internally consistent (mirror-matrix + standings reconciliation) before trusting it:

```
python3 verify.py csv/YYYYMMDD.csv
```

Exits non-zero if it finds a mismatch. No dependencies, no install step, no test suite, no linter — both scripts use only the Python standard library.

## Architecture

**Data flow:** `csv/YYYYMMDD.csv` + `assets/logo_1000.png` → `build.py` → `docs/index.html` + `docs/en.html` + `docs/style.css` + `docs/theme.js` + `docs/player-card.js` + `docs/logo.png` + `docs/beta.html` + `docs/beta-en.html` + `docs/beta.css` + `docs/beta.js`

- **`csv/YYYYMMDD.csv`** — one full snapshot per matchday. Each file is self-contained (no merging across files; the only cross-file uses are the display-only rank-change indicator and the player-card rank history below); `build.py` always picks the *lexicographically latest* filename via `find_latest_snapshot()`, since `YYYYMMDD` sorts chronologically as a string. Adding a new matchday means adding a new dated file here, not editing the old one.

- **CSV format** — a single file packs two tables separated by a non-blank "blank" row (`,,,,,,,,,,,`, detected by `all(cell.strip() == "")`, not by an empty string):
  1. **Standings**: `#,SS1,MP,W,D,L,GF,GA,GD,Pts,Rules,` — `SS1` is the player-name column (legacy label), `Rules` is freeform text (often empty, sometimes an emoji + short note like `📌2 Set`).
  2. **Head-to-head grid**: header `vs,<player>,...` (players alphabetical), then one row per player with one cell per opponent. Cells are quoted (contain commas), so must be parsed with the `csv` module, never `str.split(",")`.

- **Head-to-head cell semantics** (`classify_cell()` in `build.py`) — matches are best-of-2-sets:
  - empty → not played yet (no result)
  - `TBA` → not played yet (no result); just a note that the pair plans to play. Treat it the same as empty — neither is a confirmed fixture list, and any unplayed pair may still be played
  - one set score only (e.g. `2-3`) → match **in progress**, not yet counted in standings
  - two set scores (e.g. `4-0, 4-0`) → completed, counted in standings
  - The grid is asymmetric by design: cell `[A][B]` is A's-perspective score, `[B][A]` is B's-perspective (reversed) score. Render as-is; do not dedupe or merge the two.
  - Standings (MP/W/D/L/GF/GA/GD/Pts) are taken verbatim from the CSV, not recomputed by `build.py`. Points formula, if ever needed for validation, is `3×W + 1×D`.

- **`build.py`** — stdlib only (`csv`, `pathlib`, `re`, `shutil`, `string.Template`, `html`, `json`, `math`). Reads the latest snapshot, parses both tables, renders HTML markup directly — `render_standings_table`, `render_rules_section`, `render_h2h_table` for `index.html`; `render_beta_standings`, `render_beta_h2h`, `render_beta_page` for `beta.html` — fills `templates/index.html.tmpl` / `templates/beta.html.tmpl` via `string.Template`, copies `templates/style.css.tmpl`, `theme.js`, `player-card.js`, `beta.css.tmpl` and `beta.js` into `docs/` verbatim (only the `*.html.tmpl` files are substituted), and copies the brand logo from `assets/logo_1000.png` (`LOGO_SOURCE`) to `docs/logo.png`. Both pages share `parse_snapshot`, `classify_cell`, `format_snapshot_date` and `SITE_TITLE`/`SITE_URL`. Re-running is idempotent — it never reads its own prior output.

- **Derived `Pts/MP`** (both pages) — `Pts ÷ MP` to 2 decimals (`format_pts_per_match()`, `–` when MP is 0), computed from the CSV's own `Pts`/`MP` cells. On `index.html` it is the last standings column (`render_standings_table`); on `beta.html` it is an `x.xx/MP` line under the PTS label of each card (`.ppm`, `render_beta_standings`). Every other standings value is verbatim from the CSV; this one is display-only and never feeds anything (the beta count-up still ends on the CSV points).

- **Rank-change indicator** (both pages) — `find_previous_snapshot()` picks the next-lower `YYYYMMDD.csv` than the latest, `compute_rank_moves()` diffs the CSV `#` (rank) column between the two, and `render_rank_move()` produces a `▲N` / `▼N` / `–` span (`.rank-move`). `index.html` appends it to each player's `#` cell; `beta.html` shows it as a corner badge on the rank circle (inside a `.rankcol` wrapper). The date is only in each arrow's tooltip; there is no note under the heading. Display-only: standings values are still verbatim from the latest CSV. With only one snapshot, or for a player absent from the previous one, no indicator is rendered.

- **Latest results** (both pages): a section above Standings. `compute_latest_changes()` compares the latest grid with the previous snapshot's grid, pair by pair. A pair's status is the best of its two mirrored cells (`pair_status()`: `result` > `ongoing`). A pair is listed when its status rose: newly completed matches first, then newly started ones. Each change is shown from one player's cell as-is, using the winner's row when the mirror is also completed. `render_latest_results()` also adds a "Rank moves" line from `compute_rank_moves()` (nonzero moves only), and shows "No new results since <date>" when nothing changed. Names link to player cards on `index.html` only. Rendered only when a previous snapshot exists. Corrections to an already-completed result are not listed. Display-only. **Currently hidden:** `SHOW_LATEST_RESULTS = False` in `build.py` passes `""` instead (code kept).

- **League progress, Left and Max** (both pages). `player_match_stats()` also collects `remaining`, meaning each opponent whose cell in the player's own row is not a completed `result` (empty, `TBA` and single-set in-progress cells all count). `format_max_points()` is CSV `Pts` + 3 × remaining, labelled "if every remaining match is played", because empty/TBA cells are not a confirmed fixture list. `render_league_progress()` counts pairs where either mirrored cell is a `result` against all n·(n−1)/2 pairs and renders the `$league_progress` line and bar under the Standings heading. `index.html` shows `Left`/`Max` as the last two standings columns, each player card gets a "Still to play" block of opponent links (`render_remaining_block`), and `beta.html` adds an `x left · max N` line under `.ppm`. Display-only, never feeds standings.

- **Player cards** (`index.html`/`en.html` only; the beta pages have none) — every player name in the standings and head-to-head headers is an `<a class="player-link" href="#player-<slug>">` (`render_player_link`, `player_slug`). `render_player_cards()` pre-renders one `<dialog class="player-card">` per standings row into `$player_cards`: stat tiles (CSV values verbatim + sets/close-sets W–L from the grid), a static inline-SVG "Player Insights" hexagon (`render_radar_svg`), a "Since <prev date>" delta block (rank/Pts/MP/GD vs `find_previous_snapshot`), and the results list. Grid stats come from `player_match_stats()`, which walks the player's own row and uses `classify_cell()` — only completed cells count; single-set cells are listed as in progress.
  - **Hex axes** (`player_insights`, absolute 0–10, `–` and plotted at 0 when there's no data): ATTACK = games won per set ÷ 4 × 10; DEFENSE = (1 − games conceded per set ÷ 4) × 10; DOMINANCE = sets won by ≥3 games ÷ sets played × 10; CLUTCH = close sets (1-game margin) won ÷ close sets played × 10; FORM = CSV Pts ÷ MP ÷ 3 × 10; MOVEMENT = 5 + rank places gained vs the previous snapshot. Highest axis is highlighted. Display-only — never feeds standings.
  - **Rank history.** `load_rank_history()` reads the standings of every snapshot, oldest first. It returns short `D/M` labels and `{name: [rank or None, ...]}`. `None` means the player is absent from that snapshot or the rank isn't an integer. `render_rank_history_svg()` draws a static inline-SVG line (rank 1 at the top), broken at `None` gaps, with first/last date labels and the latest rank highlighted. It renders as a "Rank history" block after "Since" in each card, and only when the player has at least 2 known ranks. The share PNG and the beta pages don't include it. Display-only.
  - **All-player rank chart.** `render_rank_history_section()` draws every player in one bump chart, in its own "Rank history" section between Standings and Head-to-Head (`$rank_chart`, `index.html`/`en.html` only, shown when there are at least 2 snapshots). The card chart and this chart share `rank_scale()` and `rank_segments()`, so both break lines at `None` the same way. With 11 players, more than a categorical palette can separate, all lines are gray and every line has name + rank labels at both ends. Hovering or focusing a player highlights them in `--accent` (CSS only). Each player is an SVG `<a class="player-link">`, so the existing `player-card.js` click handler opens their card. **Currently hidden:** `SHOW_RANK_CHART = False` in `build.py` (code kept; the per-card rank history still renders).
  - **`templates/player-card.js`** opens the dialog with `showModal()` (deep links `#player-x` work; adds `pc-js` on `<html>`, without which CSS `:target` shows the card), and powers **Share card image**: it draws a fixed 1080×1350 PNG on a canvas from the dialog's `data-share` JSON (built in `render_player_card`) and hands it to `navigator.share({files})` (mobile share sheet), falling back to a download. The PNG is pre-rendered when the card opens so the share call stays inside the tap's user activation (iOS requirement). File sharing needs HTTPS, and `file://` taints the canvas via `logo.png` — test the PNG over `python3 -m http.server`.
  - **Player compare** — each card has a "Compare with…" `<select>` (`render_compare_picker`, `hidden` until JS unhides it). Instead of pre-rendering every pair, `render_compare()` emits one empty `<dialog id="compare">` plus a `<script type="application/json" id="compare-data">` blob from `build_compare_data()` (per-player CSV values, grid stats, insight axes, and every played/in-progress `[cls, text, outcome]` grid cell keyed by `compare_key`). `player-card.js` fills the dialog on demand: side-by-side stat rows (better side highlighted), both mirrored H2H cells as-is, an overlaid two-colour hexagon, and **Share compare image** (1080×1350 PNG, same pre-render rule). Deep link: `#compare-<a>-vs-<b>`, resolved against known keys. Display-only.
  - **Match replay** — in `render_h2h_table`, the text of each `result`/`ongoing` cell is wrapped in an `<a class="match-link" href="#match-<row>-vs-<col>">` (still verbatim). `render_match_dialog()` emits one empty `<dialog id="match">` (`$match_dialog`). `player-card.js` fills it from the existing `compare-data` cell: a mini SVG court rally plus a scoreboard that ticks up game by game and always ends on the CSV set scores. The game order is a seeded shuffle that is stable per match and closes each set on its winner. It is illustrative and the dialog says so. Single-set cells end with "in progress" and no set winner. Skip/Replay buttons are included. Under `prefers-reduced-motion` the final score shows at once. Deep link: `#match-<a>-vs-<b>` (shares `pairFor()` with compare). Display-only, no share PNG.

- **`assets/`** — hand-provided binary brand assets (currently just `logo_1000.png`), as opposed to `templates/`'s text sources. Not generated, not templated — if the logo changes, replace this file and rerun `build.py`.

- **`templates/`** — HTML/CSS/JS sources. `templates/index.html.tmpl` and `templates/beta.html.tmpl` use `$placeholder` substitution (title, description, snapshot/page/image URLs, snapshot date, table/board HTML blocks, etc.), including Open Graph/Twitter Card meta tags (`SITE_URL` in `build.py`) so shared links preview with the site's title, description, and logo. Section order on both page sets: Latest results, Standings, Rank history (index pages only), Head-to-Head, Rules last (Latest results and Rank history are currently hidden by the `SHOW_*` flags). Because of `$` substitution, never put a literal `$` in an `*.html.tmpl`. `docs/` is 100% generated output and should never be hand-edited — always change `templates/`, `assets/`, or `build.py` and rerun.

- **`beta.html`** — an animation-heavy, dark-only restyle of the same data, published alongside (not replacing) `index.html`. It is `noindex`, isn't linked from `index.html`, and links back to the classic view.
  - **Sources:** `templates/beta.html.tmpl`, `templates/beta.css.tmpl` (tokens on `:root`, dark-only), `templates/beta.js`. Standings render as ranked cards (`<ol class="board">`); the head-to-head grid is a tinted heatmap. `render_rules_section(section_class=...)` is shared with `index.html`.
  - **Data rules unchanged:** standings values come verbatim from the CSV, the grid is rendered as-is (both mirrored cells), and empty/`TBA` are both "not played yet" (TBA only gets a dashed outline). `cell_outcome()` (win/draw/loss tint and W/D/L letter from the set scores) is display-only and never feeds standings.
  - **Progressive motion:** an inline head script adds the `js` class and removes it again after 4s if `beta.js` never boots (`data-boot` on `<html>`); all motion rules are gated on `html.js`, and disabled under `prefers-reduced-motion` and `print`. Reveal-on-scroll uses `IntersectionObserver` with an on-screen fallback after 1.5s. Animated point totals always end on the CSV value (a timeout guarantees it) — keep that guarantee if you touch the count-up.
  - **Testing:** the intro, count-up and confetti depend on `requestAnimationFrame`/timers, so headless `--virtual-time-budget` screenshots show them half-finished (and headless `--window-size` narrower than 500px still lays out at 500px wide, then crops the screenshot — emulate device metrics over CDP to test phone widths). Verify motion in a real-time browser session, e.g. Chrome DevTools Protocol with device-metrics and reduced-motion emulation.

- **Languages (Thai default, English toggle)** — `main()` loops over `LANGS` and pre-renders every page once per language: `index.html` + `beta.html` are Thai (`<html lang="th">`), `en.html` + `beta-en.html` are English. There's no runtime string swapping. The `ไทย | EN` switch in each header (`lang_head()`, `$lang_toggle`) is a plain link; `theme.js` / `beta.js` append the current `location.hash` on click (delegated `click`/`auxclick` handlers) so an open card/compare survives the switch. A modal dialog makes the header switch inert, so `player-card.js` clones it into each dialog's `.pc-head`. The Thai index is linked as `./`, not `index.html`, to match `og:url`/hreflang. Compare-row labels come from `TEXT` via `compare-data.labels`, not `I18N`. Each page gets `hreflang` alternates and `og:locale`.
  - **Build-time strings:** `TEXT = {"en": {...}, "th": {...}}` in `build.py`, read via `t(lang, key, **kw)`. Values are plain text (no markup or entities): use `te()` (escaped `t()`) wherever a string lands in HTML, plain `t()` for JSON/canvas. Every render function that emits text takes `lang`; templates get `$l_*` placeholders. English values are the original literals. **Adding a string means adding the key to both languages.** Thai dates are `format_snapshot_date(path, "th")`: Thai month abbreviations with the Buddhist Era year (+543), e.g. `19 ก.ย. 2569`.
  - **Runtime strings** (compare dialog, share PNGs): the `I18N` dict at the top of `templates/player-card.js`, picked by `document.documentElement.lang`. Axis labels and W/D/L letters arrive pre-translated in the `data-share` / `compare-data` JSON (`axis_label()`, `outcome_letter()`); `INSIGHT_AXES` keys themselves never change. Share links use the JSON's `page` URL, so they point back to the same-language page.
  - `classify_cell(..., lang="en")` only translates the TBA text and tooltips; its `cls` values are language-independent, so `verify.py` is unaffected. CSV data (player names, the Rules column) is shown as-is. `SITE_TITLE` stays English (`render_title_letters` splits it per character, which would break Thai combining marks).
  - Thai CSS: Thai fonts are in the `font-family` stacks (and the canvas `FONT`), and `:lang(th)` rules drop `letter-spacing`/`text-transform` on the small caps-style labels.

- **Theming** (`index.html`/`en.html`; `beta.html` is dark-only with its own tokens in `beta.css.tmpl`) — a green "tennis court" palette (CSS custom properties in `templates/style.css.tmpl`), supporting both light and dark mode. Dark mode follows `prefers-color-scheme` by default; a manual toggle (`templates/theme.js`) overrides it via `data-theme` on `<html>` and persists the choice in `localStorage`. Variables are defined in `:root` (light), re-declared under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])`, and again under `:root[data-theme="dark"]` for the explicit override.

## Verification workflow

There's no automated test suite; after any change under `templates/` or `build.py`:
1. Run `python3 build.py` and check it prints the expected source snapshot and no warnings (it warns on stderr if standings and head-to-head player lists diverge).
2. Re-run it and diff `docs/` output (e.g. `md5`) to confirm the build stayed idempotent.
3. Open `docs/index.html` (and `docs/beta.html` if you touched anything it uses) in a browser to visually check the change; check the English pages (`en.html`, `beta-en.html`) too if you touched any text. If you only changed beta-specific files (`beta.*` templates or `render_beta_*`), `docs/index.html` and `docs/en.html` should be byte-identical before and after — check their `md5`.

After adding or editing a CSV snapshot specifically, also run `python3 verify.py csv/YYYYMMDD.csv` (see Commands) — it reuses `parse_snapshot`/`classify_cell` from `build.py` as the single source of truth for what counts as a completed match, so it stays in sync with the site's own rendering logic.
